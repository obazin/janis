# Janis — Feature Specs

The canonical description of user-facing behavior. Every new feature lands here before its task is done (CLAUDE.md rule 11).

## App shell

- **Titlebar** — prism logo mark + JANIS wordmark + "Open source" badge; centered search field. The field filters the Library, Local Files and Radio screens live, ignoring case and accents: "beyonce" finds "Beyoncé". Where the system draws its window buttons over the title bar, the bar leaves them room; its empty areas drag the window.
- **Sidebar** — three sections (Playing / Library / Sources) + Settings pinned at the bottom. Active row: pink→violet wash + accent ring.
- **Mini player** — persistent bottom bar: current art + title/artist (click → Now Playing), prev/play/next, the track overview (or, for a station, the live mini oscilloscope), EQ button. Playback continues across all screens (task lifecycle independent of UI).
- **Track overview** — while a track plays, local or from Jellyfin, the bar shows the shape of the whole track as a DAW draws an audio clip: a lighter peak envelope around a solid RMS body, mirrored about a middle line, from the start of the track on the left to its end on the right, normalised to the track's loudest peak (a near-silent track is not scaled up). The part already played takes the waveform gradient, the rest is muted, and a white playhead marks the position; a click seeks there, and a thin line follows the pointer over it. The shape is read in the background when the track starts, filling from left to right as it arrives: a file on the internal disk takes a fraction of a second; a file on a network share as long as the share takes to deliver it; a Jellyfin song is read from a small mono MP3 the server transcodes for the purpose (64 kbit/s, about half a megabyte a minute), or from the original file should the server not transcode, and starts drawing within about a second. Until the shape arrives a middle line stands for the track. The last eight shapes read are kept for the session, so going back to a track draws it at once. A track whose shape cannot be read at all shows the oscilloscope instead; a station always does. The playhead moves by whole pixels, so the window is redrawn only when it actually moves.
- **Boot** — the window opens only once the preferences and the library are read, so screens always show hydrated state. Volume, EQ, playback switches and language persist in `janis.db`.
- **OS drag-and-drop** — dropping audio files anywhere in the window imports them; what is not an audio file is left out.
- **Error toasts** — failures surface, they never fail silently. A `Toaster` mounted in the shell shows an error toast (click to dismiss, auto-dismisses) whenever playback fails (the engine reports an unplayable/unreachable track), a radio station won't connect, a Jellyfin sync fails or the server signs Janis out, or cover art can't load — playback failures and cover failures are each deduplicated by key, so a disconnected source (e.g. a NAS or a Jellyfin server going offline mid-session) raises one toast, not one per track, for as long as that toast is showing. Messages carry a translation key, not resolved text, so a toast follows a change of language. Cover tiles whose art was expected but failed to load show a muted "unavailable" mark rather than the normal gradient, so a failed load reads differently from art that simply doesn't exist.
- **One instance** — launching Janis while it runs brings the running window to the front instead of starting a second one.

## Now Playing

- Empty state (nothing loaded): icon + "Add music" CTA → file picker.
- Left column (sticky): album art — embedded cover art when the file has one, else a deterministic prism-gradient tile with title initials, the gradient of its album's card (a song on no album has one of its own) — ringed by a conic glow that turns slowly while something plays. Below: quality badge ("Hi-Res · FLAC 24/96" — Hi-Res when >16-bit or >48 kHz) and a lime "Lossless" badge for lossless formats. Radio mode shows genre + LIVE badges instead.
- Right column: pink eyebrow ("NOW PLAYING · FROM {ALBUM}" / "LIVE RADIO · {STATION}"), hero title, artist / composer (teal, only when tagged) / album columns. In radio mode the hero shows the track the station is playing, falling back to the station name, with artist and album columns when known and station + genre beneath. A star follows the station name: an outline while the station is not a favourite — which every station is until starred — and filled pink once it is; a click flips it, and the choice is kept across launches. The art tile shows real cover art from stations that publish it.
- **Waveform** — live time-domain oscilloscope over the playing signal, taken from the engine's analyser after the EQ and gain, so the trace scales with the volume slider (synthetic animation only when nothing is playing). Progress wash + playhead dot; click seeks (tracks only, not stations); a seek while paused moves the playhead at once. Time row shows elapsed / total ("Live" for radio).
- **Transport** — shuffle (accent when on), prev, gradient play/pause that pulses while something plays, next, repeat (accent when on); volume rail with pink→teal fill, persisted debounced.
- **Queue card** — three-way segmented toggle: **Up Next** (remaining queue after the current track, wrapping once; with shuffle on, the same tracks unnumbered under a "shuffled" heading, since the order they will play in is drawn by the engine), **Playlist** (the full play queue, current track highlighted), **Album** (the current track's album from the library grouping). Rows show art, title/artist and duration; clicking a row plays from it. An "EQ" pill in the card header opens the equalizer overlay. The toggle survives navigating away and back.
- **Artist spotlight** (local tracks with library matches) — two columns under the queue card: up to 4 more tracks by the current artist (click plays within the artist's tracks) and up to 4 of their albums (click plays the album).

## Library

- Header: violet eyebrow, title, gradient "Add music" button (multi-file picker).
- Tabs (chips): **Playlists** (roadmap placeholder), **Artists** (grid), **Albums** (grid), **Songs** (numbered rows: art, title/artist, composer, duration; click plays from that row within the filtered list).
- The three lists are alphabetical: artists by name, albums by name (then artist; untitled albums last), songs by artist, then album, then title (a song without an artist or an album after those with one). Case and accents are ignored, and so is whatever comes before the first letter or digit, so "'Round Midnight" sits with the R's. A search filters the lists without reordering them.
- Clicking an album or artist tile browses it rather than playing it: an accent ring marks the selected tile, and its tracks expand inline under that tile's row — an accordion panel spanning the full grid width, showing the album's tracks in running order, or the artist's tracks album by album (albums alphabetical, each in running order, every row titled "Album - Song" as in "Electric Ladyland - Voodoo Child"), with a close button, so browsing a large collection never means scrolling past the whole grid to reach the list. Opening a tile always lands the same way: the page glides until the opened tile's row sits at the top of the scrolling area (as far as the end of the page allows), the panel open before folds away with its tracks still in it, and the opened tile's tracks unfold beneath it, each movement taking 200 ms, easing out. When the panel open before lies above the opened tile's row, folding it moves that row, so the unfolding waits for the fold and the glide to finish; otherwise (nothing open, the same row, or a panel further down) all three run together. Closing a panel, by its button or by clicking its tile again, folds it the same way; switching tabs closes it at once. Clicking a row plays from that list. Re-clicking the selected tile, closing the panel, or switching tabs collapses it. The active tab and the selection both survive navigating to another screen and back — they live in the application controller, not the screen (CLAUDE.md rule 6).
- "Recently added" rows (the 8 newest additions the search keeps) under the grid tabs when nothing is selected.
- Empty library → empty state with "Add folder" CTA. Titlebar search filters every view.

## Discover

- Teal eyebrow. Shelves derived from the local library only: "Recently added albums", "Rediscover" (oldest additions), "Artists in your library". Horizontal scroll tiles; click plays the group. Empty library → explanatory empty state.

## Web Radio

- Ember eyebrow. A "Favourites" chip on a line of its own, then two chip rows: country chips ("All" first, then every country present, most-populated first) above genre chips ("All" first, then every genre present sorted by label in the active language). The country chips show the country name only (no flag). Both rows are multi-select — clicking a chip toggles it, so several countries and several genres can be active at once; "All" is a clear that deselects everything in its row, and an empty row means no filter. A station shows when it matches any selected country **and** any selected genre. The "Favourites" chip toggles a filter that keeps only the starred stations, within the selected countries, genres and the search; when none is left, a line says how to star one. Selections survive navigating away and back. Station cards: gradient tile, name — followed by a small pink star when the station is a favourite — genre · kbps, red LIVE dot. Click streams the station through the engine, so the EQ and the live visualiser apply exactly as they do to a local file. The card shows "Connecting…" while the stream buffers, then "Live". Active station gets an ember border. Search filters by station name **and** genre label, within the active countries and genres.
- The catalog ships ~1,350 stations across 25 countries (Europe, the UK, the USA, Brazil and the Maghreb: Morocco, Algeria, Tunisia) and ~45 genres, Arabic music and Quran stations among them, baked in as static JSON. It merges the hand-picked flagship streams — the SomaFM channels, the Radio France webradios (FIP, France Musique, Mouv'), Radio Paradise mixes, Radio Swiss, French independents (TSF Jazz, Nova, Meuh, Jazz Radio, FG, OÜI FM, Latina), US public/independent stations (KEXP, KCRW, WFMU, KUSC, WQXR, The Jazz Groove, SmoothJazz.com), international independents (NTS, Rinse FM, dublab, Venice Classic) and electronic specialists (Nightwave Plaza, Nightride FM, Ambient Sleeping Pill, Hirschmilch, Sunshine Live, Bassdrive) — with the most-listened stations per country from the [Radio Browser](https://www.radio-browser.info) community database, plus tag-targeted top-ups for genres the per-country lists leave thin (jazz, funk, blues, rock, pop, classical, bossa nova), deduplicated and genre-mapped at build time. No network call is made to browse; only the chosen stream is opened.

## Library metadata

- The scanner reads tags through `lofty`, which normalises every container onto the same keys — ID3v2.2/2.3/2.4 and ID3v1 in MP3, Vorbis comments in FLAC and OGG, MP4 atoms in M4A, APE — so no format needs special handling. Title, artist, album, album artist, composer, genre, year, track and disc numbers (with totals) and embedded cover art all come from there.
- **A missing track number is recovered from the filename**: `07 - Alive.flac`, `2-11 Reprise.mp3`, `104 Title.m4a`. Only leading digits count and only when a separator follows them, so `1984 - Track.mp3` is not read as track 198 and `99Luftballons.mp3` is not read as track 99. A leading `N-` or `N_` is taken as the disc.
- Albums group by album + **album artist**, so a compilation stays one album instead of splintering per featured artist, and their tracks are ordered by disc, then track, then title. Tracks with no position sort last rather than to the front.
- **Cover art shows everywhere a track or album appears**: Now Playing and the mini player, the queue card and artist spotlight beneath it, the Library album/artist grids and track rows, and the Discover shelves. Only radio cards stay a gradient by design.
- Art is read from every tag block in the file, not just the primary one, preferring the front cover and accepting a back cover over nothing. A track with no picture of its own falls back to the rest of its album, so a rip where only the first file is tagged still shows the sleeve throughout.
- Tiles fetch art only once they have stayed in view for a moment (a tenth to a fifth of a second), so a fast scroll does not queue the covers of every tile it flew past and the tiles where it stops fill first. At most four covers load at once, decoded off the interface thread and cached per cover (300 covers at most; the songs of a server album that show its picture share one), so a large library never loads it all at once and a media server is never flooded. Once the album or artist grid or the songs list has rested for a quarter of a second, the covers of a screenful beyond each edge of what it shows load ahead, the side it was scrolling towards first, so a short scroll lands on covers already there; this prefetch takes at most two of the four loaders and waits while any tile in view does. The art of what plays loads apart from the tiles, never waiting behind them. Until a cover arrives, and for albums that genuinely have none, the generated prism gradient stands in.
- Now Playing shows the track's position on the record ("Track 4 of 9"), disc when there is more than one, year and genre. Titlebar search matches album artist and genre alongside title, artist, album and composer.

## Playback engine

- **Volume normalization** evens out loudness across the library, against −18 LUFS (the ReplayGain 2.0 reference). A track plays at its album gain when one is known, so the songs of a record keep their differences, else at its track gain, else at its measured loudness, else unchanged. Gains come from a file's ReplayGain tags, and from a Jellyfin server's own normalization gains. A local file without any is measured against EBU R128 in the background, decoding faster than real time, at start-up and after every scan, so it has a gain before it is first heard. The measurement runs at the lowest priority the system offers: it gives way to playback, the interface and every other application, and stays off a processor's performance cores, so a library full of new files does not keep a laptop's fans running; files on a network share are measured more slowly, since their reads give way too; a file that cannot be measured is tried again at the next launch. A gain measured while Janis runs applies from the next queue loaded. A track still without a gain (a server song the server has not measured) is measured while it plays and recorded only when heard start to finish; a seek abandons that measurement rather than storing a partial one. A boost is held 1 dB under the track's peak where a peak is known, and takes effect exactly as each track reaches the speakers, which matters at a gapless join where two tracks are in flight at once.
- Decoding, the 10-band EQ, the analyser and output all run in Rust. One signal path for every source: file **or web radio stream** → symphonia decode → resample (bypassed when the source already matches the device rate) → ten peaking filters → volume + normalization gain → analyser tap → device. The analyser sees the final signal, so the visualiser scales with the volume slider — that is by design, not a canvas bug.
- Web radio is buffered over HTTP into the same decoder a file uses, so a station gets the EQ and a real visualiser. A dropped connection is reopened automatically, backing off from a second to half a minute across eight attempts before the station is reported as unreachable — servers restart, and falling silent is the wrong answer to something that fixes itself.
- **What a station is playing** comes from one of two sources. Stations whose operator publishes a now-playing endpoint (SomaFM, the FIP and France Musique webradios, Mouv', Radio Paradise — 64 of the curated list) are polled for artist, title, album and cover art; Radio France and Radio Paradise supply the artwork, and Radio France says when the track ends so the next poll lands just after it. Everything else falls back to the ICY metadata carried in the stream, parsed into artist and title where its shape allows. A station with a provider ignores ICY: two feeds disagreeing about timing reads worse than either alone.
- **Track transitions** follow whichever of the two switches applies, checked in this order. Crossfade, when on, overlaps the last four seconds of the outgoing track with the start of the incoming one, faded with an equal-power curve so the perceived loudness does not dip at the midpoint; a seek, a manual skip, or turning the switch off cancels a fade already in progress rather than letting it finish. Otherwise, gapless (on by default) joins the next track directly in the playback ring with no flush, so a continuous-mix album plays with no gap or click; turned off, each track instead flushes to a clean, brief silence before the next one starts, like most other players' default behavior.
- The engine owns the queue and the transport; the interface mirrors engine state and sends commands, so playback is independent of what is on screen.
- Pressing Play after a queue has run its course starts the last track again rather than doing nothing, and switching the output device mid-track continues playback on the new device at its own sample rate and channel layout.
- **Shuffle** walks a real permutation of the queue, so every track is heard once before any repeats, and reshuffles when a repeating queue wraps.
- The visualiser is fed by the engine at ~60 Hz as a compact binary frame (160 waveform points + 10 band magnitudes).
- The track overview is read by the engine too (`AudioEngine::read_overview`): the track is decoded from end to end, separately from playback, and reduced to one slice per hundredth of a second holding the lowest and highest sample of its mono mix and their RMS.

## Jellyfin

- **Settings card** — a "Jellyfin" section between Audio output and Language. Signed out, it asks for the server address (`jellyfin.local:8096`). A bare host such as `192.168.1.20` gets Jellyfin's defaults, `http://` and port 8096; an address typed with `http://` or `https://` keeps that scheme's own port, as a reverse proxy expects; a path such as `/jellyfin` is kept, the user name and the password, with a Sign in button (Return in the password field does the same). Signed in, it shows "Connected to Jellyfin", the server's name, the user and how many of its songs are in the library, with **Sync now** and **Sign out**. A line under the card says what is happening ("Signing in…", "Reading the server's songs…") or what went wrong: no address, no user name, a server that does not answer, an address where something other than Jellyfin answers, refused credentials. The fields keep what was typed when leaving Settings and coming back.
- **Credentials** — the password is sent once to sign in and kept nowhere: the field is cleared as soon as it is read, and `janis.db` keeps the address, the user and the access token the server returns. Janis names itself "Janis" to the server, with a random device identifier made once per installation.
- **Songs in the library** — once signed in, every song the user can see on the server joins the library: Library (artists, albums, songs), Discover, the titlebar search, Now Playing, the queue card and the artist spotlight, grouped and ordered with the local files by the same rules (title, artists, album, album artist, composer, genre, year, track and disc numbers, duration, format, sample rate, bit depth, channels, lossless). The Local Files screen lists only the files on disk.
- **Sync** — the server's songs are read at launch (in the background; the window opens on the songs already known), after signing in, and on **Sync now**. A sync adds new songs, updates changed ones and removes the songs the server no longer lists. A sync that cannot read the whole listing changes nothing, raises one toast, and leaves the card signed in so the next sync can try again. Songs keep their loudness measurements across syncs.
- **Playback** — a server song plays the original file from the server, not a transcode: lossless stays lossless, and the quality badges read as they would for the file on disk. It goes through the same engine path as a local file — EQ, normalization (with the server's gains), gapless, crossfade, seek and the live waveform — downloading as it plays; the next song starts downloading before the current one ends, so a gapless album stays gapless. A song that cannot be fetched (server down, item gone) raises the playback toast and the queue moves on.
- **Covers** — the server's picture of the song's album, or else of the song itself, at the size each tile needs, cached like any other cover: the songs of an album share one picture. A server that stops answering raises one "cover art couldn't load" toast, not one per tile.
- **Token refused** — when the server stops accepting Janis's token (signed out from the server's dashboard, password changed), a toast says so, the card asks for the password again with the address and user filled in, and the songs stay in the library; signing in again as the same user keeps them and their measurements.
- **Sign out** — ends the session on the server (best effort; signing out works offline) and removes the server and its songs from the library. Signing in to another server, or as another user, replaces the previous server and its songs: Janis keeps one server at a time. An attempt that fails leaves the current server signed in, with its songs, and the card says why.

## Local Files

- Lime eyebrow. Dashed drop zone: click opens the file picker; OS drag-and-drop works window-wide. Formats: MP3, FLAC, WAV, AAC/M4A, OGG/Vorbis, Opus, AIFF — all decoded in Rust. Opus is mono or stereo; multichannel Opus is not supported.
- Lists the files on disk only; a Jellyfin server's songs are in the Library, not here.
- "Scanned library · N files" header with the last scan report (added/updated/skipped), "Add folder" and "Rescan" ghost buttons.
- Table: title, artist, lime format chip, duration. Click plays from the filtered list.
- Watched folders list: path, track count, per-folder Remove (cascade-deletes its tracks). A folder inside one already watched is refused with a toast naming the folder that holds it; adding a folder that holds watched folders takes them over, their tracks and loudness measurements with them, and lists only the outer one. A scan follows links, to a file or a folder on another disk alike; a folder it cannot read, a link back up the tree or a link to nothing counts among the skipped files. Rescan re-walks all folders and prunes files that vanished — but only under roots that are still reachable, so rescanning with an external drive ejected leaves that drive's library (and its accumulated loudness measurements) intact.

## Settings

- Violet eyebrow. **Equalizer presets** chips (apply immediately + persist) and a "fine-tune" link opening the EQ sheet.
- **Playback** toggles: normalization, gapless and crossfade are all live in the engine, on by default; exclusive output is still a persisted preference the engine does not act on yet. Toggling normalization is heard immediately, mid-track. Gapless and crossfade take effect from the next track boundary (crossfade turned off mid-fade stops it immediately instead of letting it finish).
- **Audio output** cards: the output device the engine opened and its sample rate (both populate once something has played; "System default" / "—" until then).
- **Jellyfin** card: the server's address and credentials, Sign in, Sync now, Sign out (see Jellyfin).
- **Language** chips: English / Français. Persisted; `lang` attribute + localStorage FOUC mirror update immediately.
- Open-source banner (GPL-3.0).

## 10-band Equalizer (overlay)

- Bottom sheet over everything (scrim click / Escape / × closes). Preset chips + Reset. Ten vertical bands (32 Hz–16 kHz), ±12 dB in 0.5 dB steps, drag anywhere on the column; value readout colored lime (boost) / ember (cut). Gains apply live to the engine's filters and persist (debounced) with the preset name; hand-moving a band flips the preset to "Custom".
- **Linear phase** toggle, between the presets and the bands. Off by default, the same ten gains run as realtime biquad filters — zero latency, audible on the next buffer. Turned on, they run instead as a linear-phase FIR in the decode chain: no inter-band phase distortion, at the cost of a constant latency (about 43 ms at 48 kHz) which the row's description names once the engine reports the figure for the open device. The two modes never stack — the FIR takes over from the realtime filters while on — and a change is heard once the already-buffered audio has played rather than instantly. Persisted, and re-read from the engine on subscribe, so a reloaded window recovers the mode from audio that never stopped.

## Persistence (`janis.db`, app-data dir)

- `user_preferences` (single row): volume, EQ gains + preset, the EQ's linear-phase mode, four playback switches, language, and the device identifier Janis sends to a media server.
- `media_servers`: the Jellyfin server signed in to — its address, its identifier and name, the user's identifier and name, the access token (never the password), and when it was last synced. One row at most.
- `watched_folders`: path, added_at. `tracks`: path (unique), folder_id (NULL = ad-hoc import), tags (title/artist/album/composer/album artist/genre/year, track and disc numbers with their totals), duration, format, sample rate, bit depth, channels, lossless, added_at, the four ReplayGain tag columns (track/album gain and peak) and the measured loudness pair (`loudness_lufs`, `loudness_peak`) the background measurement fills in. A server song's normalization gains fill the ReplayGain gain columns. Upsert by path — rescans never duplicate, and the measured loudness columns live outside the upsert so a rescan cannot wipe them. A server song's `path` is `jellyfin://<server>/<item>`, its `server_id` names its `media_servers` row (deleting the row deletes its songs) and `artwork_item` the item whose picture is its cover; a rescan never touches these rows.
- Schema changes are migrations stamped in SQLite's `user_version`, so an existing library gains new columns instead of silently missing them.
- Files are only read off the interface thread: the engine reads audio, the scanner and the cover loader run on workers of their own, and so do the calls to a media server.
